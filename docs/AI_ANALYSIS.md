# P5 evidence-backed analysis

P5 implements local domain, database, API, worker and UI behavior. Hosted Supabase, provider quality, processing/rubric/language approval, cron deployment, browser journeys and measured concurrent latency remain pending. P6 reviewed replies are the next milestone. Manual CRM remains available with AI disabled.

## Configuration and upgrade

Existing projects through migration 010 apply `backend/supabase/migrations/202610070011_analysis.sql` once. Fresh projects use the current regenerated 001–012 `setup.sql`; the bundle refuses existing business tables. `setup:supabase` preserves environment values and prepares blank AI fields. Do not rerun the bundle over an existing project.

All AI variables belong to `frontend/.env.local` on the Next.js server; none use `NEXT_PUBLIC_`. Choose `OPENAI_ANALYSIS_MODEL` explicitly after model evaluation and configure `OPENAI_API_KEY`. Set `AI_PLATFORM_ENABLED`, `AI_PROCESSING_APPROVED`, `AI_RUBRIC_APPROVED` to the exact value `true` only after the respective approvals. `AI_APPROVED_LANGUAGES` is a comma-separated subset of `en,ar,mixed`; unknown/unapproved languages score zero. No model default or release approval is assumed. Owner Pilot settings configure daily/monthly operation caps, and Agency settings require processing approval plus its recorded reference and tenant AI enablement. Zero capacity blocks new reservations; blank capacity is unconfigured.

The separately authenticated worker needs the existing `CRON_SECRET` and private Supabase worker credential. An approved scheduler calls `POST /api/internal/cron/analysis` with `Authorization: Bearer <CRON_SECRET>`. GET on that route exposes only protected queue metrics. It rejects query parameters and user cookies cannot authorize it. The worker synchronizes the server configuration into private PostgreSQL policy before claiming work; changing policy invalidates old jobs. After disabling a platform flag, invoke the worker to apply the SQL kill switch and cancel eligible pending work. Already-dispatched provider calls cannot be recalled; reauthorization prevents revoked results from publishing. Disabling tenant processing/AI takes effect directly in SQL. Scheduler/hosting must support the route's 180-second execution ceiling and durable invocation; no scheduler is deployed by these scripts.

## Context and provider contract

Submission uses verified cookie identity, current tenant membership, parent lead access, expected lead version and actor-bound idempotency. No service client is used in user APIs. The queue stores a private immutable snapshot of confirmed commercial facts and at most 50 latest INBOUND customer messages, ordered by occurrence time. It excludes contact columns, name, internal/outbound notes, audit, source references and unrelated leads. Embedded email addresses, the saved phone and common international phone patterns are redacted. This is data minimization, not guaranteed anonymization of arbitrary free text; processing approval still applies. Snapshot JSON is limited to 12,000 PostgreSQL Unicode characters, with an explicit truncation flag. UTF-8 bytes and escaped strings remain bounded. Private snapshots are deleted on terminal settlement; failed attempts retain context until terminal state. Approved retention/deletion policy for persisted results/evidence remains a release gate.

The adapter calls the fixed Responses endpoint server-side with explicit model, `store:false`, `max_output_tokens:4096`, strict JSON schema, and no tools or background mode. Timeout is 25 seconds, redirects are refused and response bytes are capped at 256 KiB. It accepts only completed assistant text with known bounded usage; refusal, incomplete output, tool output, malformed JSON and invalid evidence fail explicitly. Raw provider errors, contact text and credentials are excluded from worker logs/responses. Structured output supplies shape constraints; separate validation checks exact source ID/version/quotes and supported values. [Official Structured Outputs documentation](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).

`store:false` disables Responses application-state storage for this request; it does not establish Zero Data Retention or replace organizational processing approval and provider data controls. [Official data controls documentation](https://developers.openai.com/api/docs/guides/your-data).

## Jobs, capacity and failures

An agency lock coordinates quota reservations with existing membership/settings operations. One new context job reserves one operation in both UTC day/month windows and a conservative 192,000-token allowance for up to three attempts. Active same-context work is reused without another reservation. Each user may submit ten new jobs per fixed database hour; generic HTTP/direct-write limits also apply. Operation caps are the pilot commercial unit, not a dollar-cost limit. Token observations/allowances are accounting metadata; no provider pricing or paid-plan entitlement is invented.

Each claim has a 90-second expiring lease and fencing token. The worker rechecks current requester, verified membership, parent access, tenant/platform policy and context before sending; completion rechecks access/policy and context under transaction locks. Transient timeout, rate-limit, unavailable transport and database persistence failures retry at most three total attempts with 30/60-second backoff plus jitter. Refusal, incomplete/schema/evidence/safety failures are permanent. Each invocation starts at most three jobs while its soft 35-second admission budget remains; each provider request is independently bounded. Queue progress depends on recurring authorized worker invocations, not browser polling.

Known nonbillable cancellations/failures release both operation windows. Known billable outcomes consume the operation and record observed tokens; known-unused token capacity releases. A lost response, expired dispatched lease or cancellation after dispatch keeps `RECONCILE` and remaining token allowance, retaining operation capacity. This prevents silently refunding potentially billable work. A provider request is not guaranteed exactly once; an interrupted attempt can incur duplicate provider usage, while SQL publishes at most one result per job. Owners can inspect usage/reconciliation counts. Operator reconciliation against provider billing is still manual and requires an approved recorded maintenance process; no speculative automatic refund is implemented.

Result, usage settlement, audit and notification commit atomically. Changed context after dispatch produces immutable STALE history without replacing the current pointer or emitting AI_READY. Revoked access/processing produces CANCELLED without a published result. Old workers cannot finalize expired/replaced leases. Current-parent RLS protects all job/result reads; private snapshots, leases and quota buckets are unavailable to user clients. Ready/failed notices recheck current context and recipient access when rendered/opened.

## Evidence, score and interface

Missing values stay UNKNOWN/null. Summary is empty or one mechanically verifiable safe source excerpt. Field evidence is an exact quote of at most 240 characters; instruction-bearing quotes cannot contribute evidence, and phone redaction markers cannot imply a callback. Missing facts are flagged by the server; numerical values, currency, intent, bedroom counts, requested action and timeline must have conservative textual support. Conflicts cite at least two different source messages and contribute no inferred points for the conflicted field. Human-confirmed facts take precedence for score. This conservative validator may withhold valid natural-language variants; approved model/Arabic coverage must be measured before enablement.

Scoring uses proposed-1 commercial components: intent 20, supported budget/currency 20, area 15, property type/bedrooms 15, timeline 20/10 and requested next step 10. No sensitive traits or contact completeness are used. Absolute valid dates and supported relative numerals anchor to the original message occurrence or human-confirmation timestamp; relative months are conservatively defined as 30 days, words/vague timing stay unknown. Expired timeline contributes zero. API reads project timeline points against the current clock, preserving the saved result and original target rather than resetting urgency on each read.

Lead AI analysis shows availability, queued/running/failed/cancelled state, cancellation, current/stale history, score components, uncertainty, flags, extracted facts, exact quotes/source versions and suggested clarification questions. Current authorized scores appear in the inbox. Human facts remain separate and lead status is unchanged. Polling is bounded at 30 seconds with scope cancellation and 429 backoff; historical pages have 25 jobs. Preview provides availability guidance and generates no fabricated analyses. There is no automatic reply delivery, draft approval or qualification in P5.
