## Product outcome and boundaries

Build an English, responsive, multi-tenant lead workspace for UAE real estate agencies. An owner sets up an agency and team; managers capture and assign inquiries; agents review supported needs, contact customers externally, record what happened, schedule follow ups and explicitly record outcomes. Managers can see ownership, stalled work and overdue tasks.

MVP includes all BR01–BR14 / F01–F14: verified accounts, tenancy, team administration, manual/CSV/signed website intake, duplicate review, pipeline, manual conversations, evidence-backed AI analysis, reviewed reply drafts, tasks and in-app reminders, authorized dashboard, audit, privacy and reliable operations. Commercial administration stays manual during the pilot.

Customer text can be multilingual; the interface is English. AI never sends messages, selects a sales outcome, promises inventory or financing, or grants access. Copying a draft and logging an actual external message are separate actions. WhatsApp/email sending, billing, exports, Arabic UI, property inventory, calendars, RAG and advanced reporting are future releases with their own gates.

## Architecture and development rules

- Root contains exactly `docs/`, `frontend/`, `backend/`. Frontend owns Next.js configuration and environment; backend owns services, schemas, SQL migrations, tests and workers.

- Development origin is `http://localhost:4000`. Next.js route adapters call the backend workspace package on the same origin. Node >=22.18 is required; bundled Node 24 is available here.

- Keep the specified modular monolith: Next.js/React/TypeScript, Supabase PostgreSQL/Auth/RLS, shared Zod. Tailwind/shadcn and React Hook Form adoption remains an explicit UI deliverable. Use durable PostgreSQL jobs/outbox for background work; requests and process memory are not durable queues.

- Separate development, staging and production configuration. User requests use verified cookie identity and active agency membership, not a service-role client. Narrow server workers use protected credentials and explicit tenant/parent authorization.

- Add fields through numbered migrations. Preserve tenant-safe child foreign keys, default-deny writes, stable pagination, expected_version and transactional audit. Retryable operations bind actor, tenant, operation, key and input hash; replay rechecks current access.

- Every milestone ships database/domain/API/UI behavior, safe errors, meaningful negative tests, documentation and migration instructions. Client role visibility supplements server authorization.

- AI and quotas never disable manual CRM. Persist UTC, show agency timezone, keep unknown facts explicit, and preserve user drafts after recoverable failures.

### P1: Everyday lead controls

1. Expose contact/budget editing through the existing replacement API, retaining fields on conflict. Show versioned state and explicit contact/budget validation.

2. Managers change lead assignment to an active same-agency member or unassigned. Preview OPEN task count and require transfer confirmation. Transfer OPEN tasks to the new assignee; unassigned OPEN tasks become manager-queue tasks. Preserve completed/cancelled attribution. AGENT cannot assign. Later P3 emits notifications from these events.

3. Managers archive with reason and cancellation confirmation; archive all OPEN tasks atomically and hide archived leads from default inbox. Restore preserves lifecycle and does not recreate tasks. A restored terminal lead still requires reopening before outreach.

4. An editable user can enable do-not-contact with reason; cancel OPEN outreach tasks while preserving INTERNAL tasks. Only a manager can clear with documented basis. Existing outbound/task gates enforce the saved preference. Future AI drafts obey the same preference in P5–P6.

5. Read-only activity timeline shows actor/time, business event, reason and relevant changes. Audit writes remain inaccessible directly. Contact values are not unnecessarily duplicated into audit.

6. Inbox uses server search/status/archive filters and cursor paging; preview remains visibly session-only. Manager directory exposes only same-tenant active assignment choices, not privileged Auth records.
