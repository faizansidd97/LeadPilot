1 Purpose and conventions
This FSD defines MVP behavior and extension points for LeadPilot AI, alongside LP BRD 001. F 01 to F 14 are MVP requirements. F 15 to F 17 are roadmap only. A 01 to A 24 are minimum acceptance evidence. SHALL indicates required behavior; proposed configurable limits require approval. Roles belong to agency memberships, not global users.
2 Architecture and deployment
Use a modular monolith: Next.js 16 App Router React TypeScript Tailwind/shadcn React Hook Form and shared Zod validation. Route Handlers expose JSON APIs; Server Actions call the same domain services. Supabase Auth supplies identity, PostgreSQL stores business records, RLS restricts access, Responses API runs server side, and Vercel hosts web and bounded cron calls.
Modules: identity and tenancy, leads, conversations, AI orchestration, follow ups, notifications, administration, audit, usage. PostgreSQL durable job rows and transactional outbox support bounded workers. Do not rely on requests continuing after response or in memory queues surviving deployment.

3 Identity tenancy and permissions
3.1 F 01 Access and onboarding
MVP uses verified email and password with Supabase Auth reset and verification flows and approved transactional email delivery. User without membership may create agency or accept invitation. Agency create is idempotent and atomically creates exactly one owner. Fields: agency name 2 to 120 characters, IANA timezone default Asia/Dubai, locale en. Checklist: agency details, approved processing settings, invite, sample lead and reminder.
Multiple memberships require active agency choice. Switching clears tenant cached data and filters; every server request revalidates membership. Invitations store hashed single use token, proposed 72 hour expiry and normalized email. Valid acceptance requires same verified email and atomically consumes token. Resend revokes prior token. Pending invites reserve seats; expiry releases them. Failure reveals no other agency or account information.
3.2 F 02 Authorization
Tenant is resolved from verified membership or integration credential; payload tenant selector is not authority. RLS checks active membership on tenant tables. AGENT can access only currently assigned leads and children. Database membership checks prevent disabled membership remaining active until JWT expiry.

5 F 03 Lead intake
5.1 Manual entry
Require full_name and valid email or phone. Optional: initial_message intent budget_min budget_max currency budget_period locations property_type bedrooms purchase_timeline source and notes. Managers choose active assignee or unassigned; AGENT creates self assigned. Create sets NEW, MANUAL, server creator and times. Initial message becomes INBOUND in same transaction.
Tenant scoped exact normalized contact match returns a candidate warning, never overwrites. Managers open existing or create separate with reason. AGENT sees only accessible candidates; inaccessible match produces generic manager review flag and self assigned new lead without revealing identity. Match keys: case insensitive normalized email or international phone. No fuzzy identity verification or automatic merging.
5.2 CSV import
Managers upload UTF 8 CSV, proposed maximum 5 MB and 1,000 rows. Provide header template, mapping, and 20 row preview. Columns mirror create; assignee_email must match active member. Reject tenant, creator identity, and role columns rather than accepting caller authority. Duplicates skipped by default; manager can create separate with batch reason.
Validate all rows first and show row field and reason. Confirmed import processes valid rows in bounded transactions; invalid rows do not block valid rows. Durable import_id and row_index uniqueness prevents duplicate replay. Show created duplicate failed counts reconciling to input total and permit retry of retryable failures only. Raw file removed after processing under approved policy. Formula like values remain text and future exports must sanitize them.
5.3 Website webhook
POST /api/v1/intake/{integration_id}/leads verifies HMAC SHA 256 over timestamp and raw body, proposed five minute skew, unique external_event_id, active integration and limit. Integration maps to tenant; reject payload tenant creator and arbitrary assignment. Configured active default assignee or manager queue. Source WEBSITE includes source reference ingestion time and supplied customer message time.
Secret shown once to manager, stored encrypted with server key, rotatable and revocable with key version. Do not embed signing secret in browser JavaScript: website backend signs. Browser only form intake is a later protected design. Idempotency key (tenant integration external_event_id) and body hash: identical replay returns original result; changed payload returns 409. Duplicate contacts create review flagged lead without merging. 201 create, 200 replay, 422 invalid, 401 signature failure, 429 limits, 503 temporary failure. Sender retries transient failures with same event id.

7 F 05 Conversation and notes
Text timeline per lead stores direction INBOUND OUTBOUND INTERNAL, channel MANUAL WEBSITE or future adapter, body, occurred_at, created_at, author and provenance. WEBSITE input is inbound. Manually logged outbound delivery status is USER_REPORTED, never delivered or read. Internal notes are visually distinct and excluded from AI context by default.
Agent logs incoming text, external contact attempt or actual outgoing reply. Mark as contacted writes explicit outbound event and proposes CONTACTED for confirmation. Manual message edits store revisions and audit; provider supplied messages are immutable. Order occurred_at then created_at then id. New or edited customer text increments context_version and marks analysis stale. Escape HTML, safe links only; no attachments sync or unsupervised sends. Reject future timestamps; historical import is allowed with source label.
8 F 06 AI analysis
8.1 Jobs context and freshness
Analyze requires access, active lead, approved processing settings, tenant AI enabled, rate and quota capacity. Atomically reserve usage and queue durable job. Snapshot confirmed fields and latest customer messages only; omit contacts internal notes audits unrelated leads sensitive documents. Proposed 12,000 character cap sets truncation flag. Persist input_version and request hash.
Call Responses API server side with schema constrained output and store false baseline. This is not zero retention assurance; approve provider processing separately. No tools browsing or external retrieval. Quoted messages are untrusted data, not application instructions. Zod validates every returned field. Refusal or incomplete output becomes explicit safe failure, not forced plausible result.
Job states QUEUED RUNNING SUCCEEDED FAILED CANCELLED. Database lease and expiry claim bounded work. Retry transient timeout rate limit or service failure up to 3 total attempts with backoff and jitter. Schema failures do not loop indefinitely. Unique job result prevents repeated save. If context_version changes, retain result as STALE without promoting current pointer. Lost leases are recoverable. Cancellation or deactivation is rechecked before publishing result.

8.4 Guardrails and evaluation
Evaluate at least 100 approved deidentified inquiries covering English Arabic mixed language unknown currency rent periods conflicting facts injection and unsafe response cases. Proposed gate: 95% supported populated fields, zero critical tenant leakage and no automatic sends. Review language slices separately; unvalidated language remains an acknowledged limitation. Capture usefulness and unsafe feedback.
Adversarial text cannot invoke tools because none exist; server context isolation prevents unrelated retrieval. Withhold unsafe drafts and offer manual path. No invented listing availability discounts guaranteed returns visa legal or financing approval. Tenant disable and platform kill switch stop new jobs; cancel or withhold running results when required.
9 F 07 Reply suggestions
Generate with current lead context and optionally current analysis, visibly labeling stale analysis. Parameters: language, PROFESSIONAL or FRIENDLY tone, agent instruction up to 500 characters subject to system rules. Use confirmed facts; no live inventory presumed. Ask for missing details rather than invent facts.
Draft states GENERATED EDITED APPROVED REJECTED COPIED SUPERSEDED. Store original and editable text. Approval records actor time and input_version. Copy enabled only after explicit review of current version. Edit invalidates approval. New customer context makes draft stale, requiring regeneration or explicit freshness acknowledgement and review. Record rejected unsafe incorrect or unhelpful feedback.
Clipboard copy records copied event but no outbound message and no provider call. Separate Log external message saves actual sent text and user asserted time. There is no send button in MVP. Manual reply remains available even when AI fails.
10 F 08 Follow ups
Task fields: lead_id active assignee type CALL MESSAGE EMAIL VIEWING INTERNAL title due_at notes and state OPEN COMPLETED CANCELLED. Due and overdue are computed from OPEN and UTC due_at, not stored states. Managers choose members; AGENT assigned lead and self only. Title 150 and notes 2,000 proposed limits.
Create future task on active nonterminal nonarchived lead. Do not contact permits INTERNAL only. Complete requires summary and completion time; does not contact customer or alter status. Reschedule OPEN increments schedule_version and preserves audit; prior notice becomes obsolete. Do not reopen completed task; create new one.
Protected cron every proposed 5 minutes scans bounded 100 record batches. Atomic claims and unique key follow_up_id schedule_version event_type recipient prevent duplicate notices. Late scans catch up; no customer contact. Alert if oldest unprocessed due record exceeds 15 minutes. Recheck state and access before notification delivery.
Reassignment transfers OPEN tasks to new lead assignee after confirmation. Unassigned lead tasks enter manager queue and notify active OWNER and ADMIN separately. Completed and cancelled tasks do not create notices. Opening old notice shows latest authorized state.

13 F 12 Audit and F 13 Privacy
13.1 Events and evidence
Activity shows capture assignment status message revision analysis draft review copy task archive restore. Immutable event fields: id tenant actor or system actor type entity UTC time request source sanitized old and new values reason. Require reasons for closure duplicate override reopen ownership and do not contact clearing. No full messages passwords tokens or raw provider payloads in technical logs.
Critical mutations and audit insert commit together, or transactional outbox guarantees side effect retry. Approved backend functions alone write audit. Security events include denied high risk actions credentials membership support export privacy cases and job failures. Read follows agency and parent scope; users cannot update or delete evidence.
13.2 Retention deletion and support
Approve record class retention before live intake. Planning defaults: active leads until business purpose ends; archived review after 12 months; minimized AI snapshots 30 days; technical logs 30 days; audit metadata 12 months; raw imports removed within 24 hours. These are proposals, not legal rules. Document backup expiry and restored deletion replay separately.
Owner requests closure. Verified privacy cases record id scope reviewer hold if applicable execution and outcome. Disable processing and cancel jobs/tasks before purge. Purge or anonymize approved contacts messages and AI payloads; retain only justified minimized evidence. No agent permanent delete. Exceptional support requires scoped approval expiry purpose operator identity and audit. Server secret storage only; public browser config cannot contain privileged keys. High risk owner transfer closure credential rotation needs recent authentication and stronger release reviewed checks.
13.3 Security controls
Require HTTPS for browser, integration, database, and AI traffic. Use provider encryption at rest and separately encrypt intake secrets with controlled server keys. Validate server session identity using supported Auth verification, not an unverified client session object. Sign out revokes refresh capability and clears local tenant context. Membership authorization is checked on every request even while the identity session remains valid.
Proposed production baseline: OWNER and ADMIN enroll in TOTP multi factor authentication; AGENT enrollment is available. Owner transfer, agency closure, role elevation, and credential rotation require assurance level two and authentication within five minutes. Recovery is handled through a verified support procedure and cannot silently bypass role or owner protections. Confirm setup and recovery behavior during security review before release.
Use secure cookie and token handling appropriate to Supabase SSR, origin checks for mutations, a restrictive Content Security Policy, safe text rendering, and least privilege database grants. Never log Auth tokens, password reset links, signing secrets, or customer bodies in analytics. Rotate compromised credentials and invalidate affected integrations immediately. Review dependencies and high severity findings before release. Test session expiry, forged tenant selectors, role escalation, CSRF, stored script payloads, and privileged job scope as part of A 03 and A 24.

15.1 Cardinality and deletion
Agency 1 to many Membership; Profile 1 to many Membership; Agency 1 to many Lead; Membership 1 to many assigned Lead with nullable assignment. Lead 1 to many Message Analysis Draft Follow up and Activity. AI Job 1 to zero or one result of its own kind. Integration 1 to many Intake events; event references zero or one created lead. Follow up has many versioned history events and deduplicated recipient notices.
Membership removal does not cascade business deletion. Privacy purge handles child content and deidentifies retained events by approved policy. Index tenant status created_at id, tenant assignee created_at, normalized contacts, worker state due_at, and tenant lead occurred_at id. Benchmark RLS joins and aggregates with realistic child volumes.
15.2 RLS and database writes
SELECT requires active membership and manager role or parent assignment. INSERT UPDATE have WITH CHECK and appropriate USING. Column grants triggers and approved functions protect immutable tenant role and state columns; row filters alone do not stop role escalation. Membership assignment outcomes and quota reservation use narrow transactional services.
User queries use authenticated user context. Service credentials bypass RLS and must not become generic user clients. Jobs resolve trusted tenant and parent ids and explicitly enforce scope. Lock down SECURITY DEFINER functions with fixed search_path and minimal grants; no caller chosen identity authority. Views and aggregates must preserve invoker security or explicit authorized scope.
16 API contracts

Apply origin and CSRF checks for cookie mutations. Responses: data with optional pagination; errors: code message field_errors request_id retryable. Idempotency binds tenant actor operation key and hash; replay rechecks access. Proposed replay retention 7 days pending source retry agreement.

18 End to end workflows
18.1 Inquiry to outcome
1 Website backend signs stable event. 2 Validate and persist lead inbound message audit. 3 Manager assigns and agent notified. 4 Durable analysis extracts evidence and computes score. 5 Agent confirms facts and generates draft. 6 Edit approve copy send externally and log actual reply. 7 Create task and confirm FOLLOW_UP. 8 Due scan notifies. 9 Complete or reschedule, then explicitly close outcome.
Replay returns original; duplicates flag review; AI failure leaves manual route; new text makes results stale; failed notices retry; closed and do not contact leads suppress outreach.
18.2 Deactivation
Manager previews workload, selects replacement or queue, confirms. Server verifies role and version, disables membership immediately, transfers workload transactionally or resumably, suppresses old notices, notifies new assignees and audits counts. Repeat is idempotent.
18.3 AI recovery
Reserve usage and snapshot permitted context. Transient error retries within cap. Exhaustion fails safely and reconciles reservation. Last analysis stays visible with age. Explicit authorized retry creates new job. Late result cannot override newer or cancelled context.
