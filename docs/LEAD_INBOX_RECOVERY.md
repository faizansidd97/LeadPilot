## Inbox reads and opening

The verified workspace mounts by current actor, agency and role. The inbox has a cancellable request controller and synchronous action gate. Search, status and archive changes immediately invalidate the old request and hide old records before the 250 ms read debounce. Navigation, dialog opening, revision refresh and effect cleanup fence delayed responses even if transport ignores abort. Search/filter changes can cancel an in-progress read; refresh, pagination and opening cannot overlap within one current generation.

Only a validated current page displays. Projected rows bind agency, search, status and archive state; validate bounded display contacts/locations, source, version, creation time and optional score; and reject duplicate IDs, backward order or malformed cursors. Unused notes, reported customer facts, creator IDs and unexpected properties do not reach the inbox model. Scores remain a current server projection, not independent client proof of analysis evidence.

Loading/unavailable reads differ from confirmed empty results. A failed continuation keeps earlier rows in mounted memory but hides them and disables opening/paging. Retry inbox and Refresh leads are read-only first-page recovery. A current 401/403/404 clears rows and cursors. The badge indicates loaded records rather than an agency-wide total. A verified latest scoped lead read precedes navigation; cached list data cannot select a connected lead directly. Removed/denied/foreign/malformed or changed-archive targets prevent opening. The lead dialog independently loads current details and permissions.

API cursors retain the original PostgreSQL creation timestamp. Previously rounding descending boundaries to milliseconds could skip rows within the final row's millisecond. Cursor shape stays created_at/id; no SQL revision is needed. Client order/cursor checks retain microseconds, bind a next cursor to a full 25-row page's last row and reject overlapping pages. This cursor itself does not encode actor/filter identity; current client tickets bind that context and server identity/RLS reauthorize every request. Pages are current statement reads, not a frozen snapshot or proof of completeness under concurrent changes.

## Manual creation and recovery

Add lead owns a scoped dialog workflow. Managers receive validated projected assignment choices before submission; unavailable choices remain a retry state, distinct from a confirmed empty directory. Agents omit manager assignment input and the existing SQL assigns their own membership. Selected manager assignments must appear in the loaded directory; SQL independently rechecks current membership/assignment authority.

The form remains mounted on recoverable errors. A synchronous gate prevents overlapping directory/save/recovery requests. The parsed create payload and random request key are captured before awaiting. After an uncertain response, inputs remain visible but disabled and Recover lead save repeats only that original body/key. A malformed or mismatched acknowledgement remains uncertain rather than starting a new operation. Validated acknowledgement binds agency, manual source, initial version/state and submitted name/contact/manager assignment; SQL remains authoritative for the complete request hash and actor scope.

A verified creation acknowledgement changes recovery to latest-lead reads only. Completion closes the dialog and refreshes the inbox only after a validated current lead read and after the action gate releases. Failure to refresh the inbox afterward is a separate list-read error and does not repeat creation. Definitive validation/conflict errors release the pending attempt for correction; current authorization denial clears directory/retry state and unmounts private form inputs. Server replay still rechecks current actor, tenant and lead access.

Busy saves cannot be closed. Closing an idle unresolved dialog explicitly discards mounted retry state; the dialog asks users to inspect saved records before submitting again. Unmount/scope changes clear helper state and fence late completion; abort cannot undo a committed server transaction. The workspace immediately suspends inbox reads when opening a dialog and guards against a second dialog callback. No customer data or key is stored in browser storage, no automatic mutation retry/polling is added, and cookie identity is not serialized across tabs. Cross-tab changes and duplicate submissions after discarding a pending attempt still require server authority and user reconciliation.
