## Browser and request protection

Next Proxy generates 18 random nonce bytes for every matched document request, overwrites incoming nonce/CSP headers, supplies request CSP for Next rendering, and sets response CSP/private no-store. Root layout calls `connection()` to render at request time. Documents and navigation/prefetch requests use the same protection; API/Auth endpoints and framework assets bypass nonce Proxy. Fixed security headers apply to all routes through next.config.ts. This follows [Next's nonce/dynamic-rendering requirements](https://nextjs.org/docs/app/guides/content-security-policy).

Production scripts require the nonce and strict-dynamic, with inline handlers/eval forbidden. Objects, framing and base-URI changes are forbidden; forms/connect/worker/manifest default to self. Existing React/Radix styles require `style-src 'self' 'unsafe-inline'`; this is explicit style compatibility, not a fully strict style policy. Development alone permits eval/WebSockets for HMR. Third-party content is not allowlisted. Browser hydration, navigation, dialogs, Auth/MFA QR and clipboard behavior still require permitted interactive verification.

All responses receive nosniff, DENY framing, no-referrer, same-origin opener isolation and denied camera/microphone/geolocation/payment permissions. HSTS is emitted only for production HTTPS; local HTTP has no HSTS. No includeSubDomains/preload claim is made. Next's identifying powered-by header is disabled. Hosting/reverse-proxy behavior and any existing organization-wide headers remain unverified.

Production Auth redirect/cookie mutation origins require a configured base APP_URL, without credentials/path/query/hash. Public origins require HTTPS; a loopback URL cannot serve as a public production origin. Exact Origin and cross-site checks apply to cookie mutations. Failure returns a safe 503 or 403. Development stays on localhost:4000. Auth callback targets remain allowlisted, and successful password/session flows are not locally simulated.

Migration 014 adds verified-email checks to direct lead/agency RLS helpers and restrictive read policies for membership/invitation/notification/activity/privacy records. Child rows continue to require current parent-lead access. This closes direct-table reads by an active member whose email is unconfirmed, independently of HTTP/RPC identity checks. Emulated Auth tests prove these permissions; hosted claims/roles still require verification.

## Privacy review foundation

Owners request LEAD_ERASURE with a current lead version, or AGENCY_CLOSURE with a current agency version. Managers view cases and immutable review notes. Creation and triage require recent TOTP, strict fields, positive integer versions, actor-scoped UUID idempotency keys and atomic audit. Duplicate open scope is rejected. Request replay returns the current case only after current tenant/role/MFA/parent checks; mutation replay returns current state after current authority checks.

| Action | Requirement | Result |
| --- | --- | --- |
| REVIEW | Owner/admin; REQUESTED; bounded external verification reference | IN_REVIEW |
| HOLD | Owner/admin; open case | ON_HOLD with review reason |
| RELEASE_HOLD | Owner/admin; ON_HOLD | REQUESTED or IN_REVIEW depending on verification |
| WITHDRAW | Owner; not held | WITHDRAWN, terminal |

Case/actions remain manager-only; direct inserts/updates/deletes are denied to ordinary clients. Request reason, review notes and verification reference stay in scoped privacy records. General activity audit stores case ID, kind, version/state, without copied notes or verification material. Review notes are immutable and saved in the same transaction as case/audit/receipt. Settings → Privacy supports request/search, triage and paginated case/history reads; errors retain unsaved input and retry identity. Refreshing/selecting the latest version is explicit after conflict. Identity documents are not uploaded.

**There is no approval, deletion, anonymization, agency lock/closure, retention scheduler or restored-deletion replay executor.** Review holds are records, not a legal policy determination or a CRM write lock. Business data and ordinary CRM work remain available. D01/D03 processing/retention/backup/support decisions must be approved before irreversible execution is designed. A22 remains pending.

## Operational evidence

GET /api/internal/health requires server-only Bearer CRON_SECRET, rejects query scope/credentials, uses the private worker client only for worker_health_snapshot and disables caching. SQL requires service_role. It reads database reachability, due/outbox/AI age, pending/failed counts, reserved/reconciliation counts, observed tokens attributed to the current UTC job reservation month and open privacy count. It does not clean limits, claim jobs or mutate data. No tenant/customer/job IDs, text, keys or billing estimates are returned. `cost_amount` is null: token observation is not a reconciled provider bill. Alert is true for any queue age over 900 seconds, failed outbox/AI work or reconciliation; thresholds are proposed operating rules, not an SLA. Scheduled monitoring, alerts and a cost dashboard are still external/P8 work.

Optional OPERATIONAL_LOGS_ENABLED=true logs only api_result, generated request_id, status and duration_ms for handlers using the shared wrapper. No URL, query/body, actor, error text, provider response or secrets. Auth callbacks and hosting/edge logs are outside this wrapper. Keep deployment/edge log policies consistent with approved access/retention; the flag defaults off. Correlation IDs identify requests but are not identity audit records.

Recovery tests actually dump/load an isolated synthetic PGlite database and check parents/children, audit/receipts, privacy hold/notes, current RLS and expired-lease fencing. An injected migration failure rolls back schema/helper/policy changes before a successful retry. [PGlite's dump/load APIs](https://pglite.dev/docs/api) supply this local drill; it does not exercise Supabase Auth storage, cloud backups, external secrets, provider dedupe or purchased-tier RPO/RTO. No production dump is retained. Approved restore-deletion replay is unimplemented.

The measured 10,000-lead/1,000-task fixture checks 50 identities sequentially on one connection. LOCAL_LOAD_REPORT.md explicitly separates these SQL observations from HTTP/UI/concurrent/write/AI performance. Registry dependency audit recorded zero known advisories at the recorded lock/version snapshot; repeat it before release. These results are not proof of absence of vulnerabilities.
